The problem

Agent treasuries are guarded by a config file.

Autonomous agents already pay for APIs, compute, data and oracle queries — and they settle on-chain with no human in the loop. The only thing between an agent and a drained wallet today is a rigid JSON config, checked off-chain, inside the very process an attacker is trying to compromise.

A config is binary and brittle. It can't express intent, and worse — own the process, own the policy, drain the wallet. As agents scale, "trust the off-chain check" is not a security model.

How it works

Policy in English.
Enforcement on Mantle.

SENTINEL splits the problem in two — a policy a human can read, and an enforcement layer the EVM guarantees.

01

Read & decide

An LLM evaluates each proposed spend against the plain-English policy. Edit a sentence, hit save — the next transaction obeys it. No redeploy.

LLM · OpenRouter / Claude
02

Sign the approval

On approval, the policy-signer key produces a single-use EIP-712 authorization bound to the exact recipient, amount, purpose, nonce and deadline.

EIP-712 · single-use nonce
03

Enforce on-chain

SentinelVault verifies that signature before releasing a cent. No valid AI approval, no movement — guaranteed by the contract, not trusted off-chain.

SentinelVault.sol · Mantle 5003
What it unlocks

A firewall the EVM enforces.

English → enforced

The treasury owner edits a sentence and hits save. The next transaction is judged against the new rule — no JSON, no ticket, no deploy. Enforcement still happens on-chain.

Tamper-evident audit

Every decision — approve and reject — is committed to the on-chain SentinelRegistry. A public, replayable record of how autonomous capital was governed.

Dead-agent switch

Write "if idle 7 days, sweep to backup" and the heartbeat fires a real on-chain recovery transfer — same signed-approval gate, no separate monitor.
